# Общий рекорд 2048

Сайт остаётся на GitHub Pages. Отдельный Cloudflare Worker с SQLite-backed Durable Object хранит игровые сессии и одно число — лучший счёт сайта. Имена и аккаунты игроков не требуются; IP временно используется для ограничения частоты запросов и не записывается в базу. Личный рекорд остаётся в `localStorage` браузера.

## Развернуть

1. Создайте или откройте свой аккаунт Cloudflare. Для Worker с SQLite-backed Durable Object доступен тариф Free; проверьте отображаемые условия своего аккаунта перед публикацией.
2. Для macOS 10.15 загрузите папку `server` в корень репозитория `klushin-portfolio` через GitHub: Add file → Upload files. На этом шаге не загружайте файлы игры из корня архива.
3. В Cloudflare Dashboard откройте Workers & Pages → Create application → Connect GitHub, подключите репозиторий `klushin-portfolio`. Название Worker: `fedor-2048-record`; root directory: `server`; deploy command: `npx wrangler deploy`. Build command оставьте пустым. Проверьте настройки перед Deploy. Cloudflare запускает сборку на своих серверах, поэтому Node.js на Mac не нужен.
4. Скопируйте адрес вида `https://fedor-2048-record.<ваш-subdomain>.workers.dev` из Cloudflare. В `js/game-config.js` впишите его в `window.PORTFOLIO_GAME_API` без `/` на конце.
5. Загрузите обновлённые `game.html`, `css/redesign.css`, `js/game-core.js`, `js/game2048.js`, `js/game-config.js`, `js/i18n-data.js` и исходные `i18n/*.tsv` из пакета в те же пути репозитория GitHub Pages. Папка `server/` лежит в том же репозитории, но GitHub Pages её не запускает.
6. Откройте опубликованную страницу игры в приватном окне. Сверьте три показателя, сделайте ход с объединением плиток, обновите страницу: «Мой рекорд» должен сохраниться, «Рекорд сайта» должен быть одинаковым в двух браузерах.

Пока адрес Worker не вписан, игра продолжает работать локально; вместо общего рекорда стоит «—». Старые личные рекорды не переносятся в общую таблицу, потому что не прошли серверную проверку ходов.

## Что проверяется сервером

- Случайное начальное поле создаётся из серверного seed; сервер сохраняет поле, состояние генератора и номер хода.
- Клиент отправляет только направления ходов и случайный идентификатор сессии. Произвольный счёт не принимается.
- Сервер отвергает невозможные направления и ходы, устаревший номер хода, лишние поля, неверный формат, слишком большой запрос и чужой Origin.
- Сессии создаются с ограничением частоты; запросы ходов тоже ограничены. Отправка повторного пакета не удваивает очки.
- Ходы и общий рекорд сохраняются в одной транзакции; новый счёт обновляет рекорд только при превышении предыдущего.

Публичная анонимная игра не может надёжно отличить живого игрока от программы, которая действительно рассчитывает допустимые ходы. Эта защита не допускает простой подмены числа очков, но не обещает невозможного полного предотвращения автоматической игры. Для дополнительной защиты при росте трафика можно включить Cloudflare Turnstile или настройки WAF.

Локальные проверки: `node server/security-test.mjs`.
